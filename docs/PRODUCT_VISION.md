# PRODUCT_VISION

育児中の父親が、家庭を止めずに自分の時間を取るための Web サービス。

## 一文

初期 MVP は「自分時間 × 家庭運営」である。
父親が「飲みたい / ゲームしたい / ゴロゴロしたい / 朝寝坊したい」を、家族の日常を崩さずに実行できるようにする。

## 誰のためのものか

主対象は、未就学児または小学生低学年の子どもがいる父親。
同時に、その家庭のパートナーも利用者である。父親だけが得をして、家庭側の負荷が増える設計は失敗とする。

まだ一次調査はない。対象像は二次調査と初期仮説に基づく草案であり、確定ではない。

## 今見る範囲と、後で見る範囲

初期 MVP は現行 4 シナリオから広げない。
将来の検証軸は、自分時間の完走だけに閉じない。3 人で見ている次の拡張余地は残す。

| 軸 | 見るもの | 今の扱い |
| --- | --- | --- |
| SELF | 自分時間の実行。飲み、ゲーム、ソファ、朝寝坊 | MVP の本体 |
| FAMILY | 家庭が回ること。穴を先に埋め、復帰まで持つ | MVP では SELF とセットで扱う。独立プロダクトにはしない |
| PARTNER | 夫婦の認識ずれ、依頼の渡し方、突然の穴をなくすこと | MVP ではシナリオの前提に含める。専用機能はまだ作らない |
| SELF（拡張） | 自己改善。睡眠、習慣、回復の続き | 将来の検証対象。今は実装しない |

FAMILY / PARTNER / SELF は、後から足す別アプリの名前ではない。
同じ家庭の問題を、自分時間以外の面からも検証するための枠である。
検証を始めるときも、4 シナリオを増やしてから広げない。現行 4 本の完走が先である。

## 解く問題

父親の「自分時間」は、予定表に空欄があるだけでは実現しない。

- 家庭の作業が先に埋まっていない。
- パートナーとの認識が揃っていない。
- 子どもが起きたあとの復帰手順が無い。
- 「休んでいい」と言われても、実際には気兼ねや後始末が残る。

既存のカレンダーや家事アプリは、予定や分担の可視化はできる。
このプロダクトの初期は「自分時間を、家庭が回る形で実行する」ことに寄せる。

## 提供価値

利用者が得るものは、気分の良さだけではない。

1. やりたいことが、家庭側の前提付きで具体化される。
2. パートナーが何を引き受けるか、父親が先に何を終わらせるかが分かる。
3. 時間枠、中断条件、帰宅 / 起床後の復帰がセットになる。
4. 「自分だけ休んだ」ではなく、「家庭を止めずに休んだ」状態を残せる。

## 北星

父親が、罪悪感ではなく手順として自分時間を取れる。
パートナーは、突然の穴ではなく、事前に埋まった穴として受け取れる。
将来、FAMILY / PARTNER / SELF のどれを厚くするかは、4 シナリオの完走を見てから決める。

初期の成功は、4 シナリオのいずれか 1 つを、実際の家庭で 1 回完走できること。

## やらないこと

- 育児記録アプリにはしない。授乳、睡眠、体温のログは本筋ではない。
- 家事分担のポイント競争にはしない。
- 父親の娯楽を正当化するためのコンテンツメディアにはしない。
- すべての家族構成、すべての休日パターンを最初から扱わない。
- FAMILY / PARTNER / 自己改善を、MVP の画面やシナリオ追加で先に実装しない。
- 本番課金と Production deploy は、方針が確定するまでやらない。

## 原則

- 自分時間は、家庭オペレーションの一部として設計する。
- 父親向けコピーでも、パートナーを敵や管理者にしない。
- 最小の 4 シナリオを深くする。先に機能を広げない。
- 正本は GitHub latest `main` / docs / Issues / PRs。
