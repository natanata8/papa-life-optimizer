# MONETIZATION

状態: 仮説。価格も課金手段も未確定。
課金実装と Production での販売は禁止。確定は `HUMAN_REQUIRED`。

## 現時点の方針

お金より先に、4 シナリオのいずれかが家庭で 1 回完走できることを見る。
完走前に課金導線を足さない。
将来の売り方は残すが、今は実装しない。

## 誰が払うか

仮説は 3 つ。同時に取りに行かない。

1. 父親本人。自分時間の失敗を減らすための少額。
2. 夫婦の家計。喧嘩と後始末のコストを下げるため。
3. 企業の福利厚生。将来候補。MVP では実装しない。

初期に観察するのは 1 と 2 である。3 は消さない。

## 何に対して払うか

払う理由になり得るもの:

- 4 シナリオの型が、自分の家庭用に保存される。
- パートナー向けの依頼文が、毎回ゼロから書かなくてよい。
- 事前チェックと復帰手順が、失敗した回から更新される。

払う理由になりにくいもの:

- カレンダーの代替
- 家事ポイント
- AI 相談の回数

## 将来候補（今は実装しない）

話している売り方は、捨てずに残す。画面にも決済にも、今は出さない。

| 候補 | 見る理由 | 今やらない理由 |
| --- | --- | --- |
| affiliate | 自分時間の前後で、酒、ゲーム、寝具、家事代行など実用品が自然に出る | 紹介が先に立つと、手順プロダクトではなく通販になる |
| SNS / メディア | 4 シナリオの失敗談と手順は、獲得導線になり得る | メディア化すると、MVP の完走より投稿が目的になる |
| B2B 福利厚生 | 企業経由なら、個人課金より先に家庭へ届く可能性がある | 4 シナリオの実地完走がない状態では、導入資料だけが先走る |
| タイアップ | 酒、ゲーム、家具、宿泊など、シナリオ単位の共創余地がある | 原則と信頼を、案件に合わせて曲げたくない |

将来候補を消して「個人課金だけ」にしない。
同時に、候補があることを理由に Stripe、広告枠、企業向け画面を足さない。

## やってはいけないこと

- 無料範囲を狭くして、骨格段階で課金壁を置く。
- パートナーの承認を有料機能にする。家庭が回ることが本体なので、そこは無料側に置く。
- 広告で育児・娯楽の不安を煽る。
- affiliate / タイアップのために UX / ブランド原則を曲げる。
- Stripe や本番決済を、Production deploy 禁止中に入れる。

## 検証順

1. 4 シナリオの完走が、課金なしで起きるか。
2. 2 回目以降も、同じ型を開くか。
3. 保存や依頼文のために、お金を払う言葉が利用者から出るか。
4. そのあとで、affiliate / SNS / B2B / タイアップのどれが邪魔にならないかを見る。

「出ない」なら、課金ではなくシナリオの中身を直す。
